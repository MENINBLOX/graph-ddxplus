### 0.2 용어와 부호 규약 (원고에서 처음 나올 때 한 줄 정의를 붙인다)

- **같은 랭커 지식원 교체 평가**: 동결 Cypher 1-홉 랭커 코드는 고정하고 지식원만 바꿔 정확도를 비교하는 통제 비교다. 랭커의 효과와 지식의 효과를 떼어 놓는다. 원고에서는 "같은 랭커 코드, 지식원별로 조정한 설정"이라고 쓴다.
- **계보 커버리지**: 정답 질환이나 그 IS_A 하위 질환(깊이 3)에 소견 간선이 하나라도 있는 환자의 비율이다. 정확도를 잰 lineage 판정과 같은 규칙을 쓴다.
- **프로필 두께**: 한 지식원이 한 질환에 붙인 소견 개념의 수다. "간선 ≥ 1"(커버리지)보다 강한 조건이다.
- **환자 가중 / 질환 등가중**: 환자 가중은 환자마다, 질환 등가중은 정답 질환마다 1표를 준다. 질환 군집 CI는 같은 질환 집합 안의 질환 단위 변동만 반영하며, 새 질환으로의 일반화를 보이지 않는다.
- **순환(circularity)**: 평가 증례가 이미 지식원에 들어가 있는 상태다. **자기 인용률**은 평가 증례의 원논문을 근거로 단 HPOA 주석을 가진 증례의 비율이다.
- **LOPO**(leave-one-publication-out): 평가 증례가 실린 논문에서 나온 지식을 지식원에서 빼고 채점하는 누설 통제다.
- **희석(dilution)**: 같은 BM25가 더 큰 코퍼스에서 낮아지는 현상이다. 질의와 관련 없는 청크가 상위를 차지해서 생긴다.
- **입력 내 정답 명시 층**: 환자 입력에 정답 질환 키나 그 직속 상위 질환 키가 이미 들어 있는 환자다.
- **부호 규약**: 원고의 차이는 모두 "S-mix(또는 해당 문헌 그래프) − 비교 대상"으로 쓴다. 검토 문서와 §9.34의 "HPOA − S-mix" 값은 부호를 바꿔 옮긴다. 예를 들어 Phenopacket-store LOPO의 HPOA − S-mix +42.66 → −5.58은 S-mix − HPOA −42.66 → +5.58로 옮긴다.

### 0.3 원고 착수 전 처리 (끝나기 전에는 해당 수치를 인용하지 않는다)

1. **스크래치패드 계산 커밋**: 검토 문서 3절의 `SP/` 파일을 스크립트와 함께 `pilot/cache/v3/framing/dev_ref/`(이름은 예시)로 커밋한다. 대상은 개발 계보 커버리지(`overclaim/lineage_cov.json`), 프로필 크기(`adv/profile_size.py`), 개발 두께 층(`adv/symcat_profile_strata.json`), 질환 등가중(`adv/disease_macro_all.json`), PUMCH 군집(`adv/pumch_clusters.json`), 자기 인용률(`adv/hpoa_circ.json`), 개발 입력 명시 층(`adv/unified_confound.json`), D 봉인 차이 CI(`ref_paired.json`)다. 커밋 전에는 같은 내용의 커밋된 E 값(`pilot/cache/v3/framing/m2/stats.json`)을 쓴다.
2. **질환 등가중의 질환 키 정의**를 하나로 정해 커밋한다(`gold_clusters` 대 원 정답 ID 튜플). PUMCH_L의 질환 등가중 값은 이 정의에 달려 있다(+1.5 [−7.6, +11.0] 대 −0.9 [−9.5, +8.1]).
3. **LOPO 질환 등가중 값 계산**: 검토 문서 5.1 #3 해석 규칙의 기준은 Phenopacket-store의 질환 등가중 값이다. 그런데 `pilot/cache/v3/p0/hpoa_lopo/stats.json`에는 환자 가중 값과 군집 CI만 있다. 질환 등가중 값을 계산해 커밋한다. 아니면 환자 가중 값으로 보고하고, 규칙의 기준과 다르다는 점을 적는다.
4. **순수 사전 그래프 빌드 시간**: `pilot/cache/v3/p0/pure_dict/build_v3umlsnt_ns.log`에는 시간이 없다. 다시 재거나 "S-dict와 같은 빌더, 따로 재지 않음"으로 적는다.
5. **수집 비용(V5)**: 실행되지 않았다. 비용 표에는 "v3 벽시계 약 25.2 h(중단 약 9 h 포함), CPU 시간 기록 없음, v2는 분리 불가"로 둔다(`pilot/cache/v3/review/cost.md` [COL]).
6. **금지 표현 치환**: v3의 "사전 등록"(ABS-CON:15, DIS:21·27·45, MET-B:167)과 "사전 지정"(MET-A:53, REL:25, RES-A:121)을 "판정 기준과 예상을 실행 전에 커밋했다" 또는 "실행 전에 커밋한"으로 바꾼다. 증빙의 범위도 함께 적는다: "로컬 커밋 시각이며, 공개 등록부와 실행 전 원격 기록은 없다".
7. **P0 검증 지적 반영**(`pilot/cache/v3/p0/summary.md`)
   - PUMCH-ADM의 S-mix − S-dict 군집 CI [+1.30, +17.33]도 0을 배제한다. v3의 "희귀 3세트에서만" 문장을 고친다.
   - P0-3의 Top-10 안 하위 질환 칸 비율(DDXPlus-E 3.3–3.7%, SymCat-E 1.2–1.5%)을 표에 넣는다.
   - P0-2의 "사라진다"는 매크로에서만 맞는 표현이다.
8. **선택 측정(하면 좋다)**: E의 입력 명시 층으로 S-mix − HPOA를 층화한다. 저장 순위 `framing/m2/E_hpoa.json`과 `framing/input_gold/`를 쓰고 [사후]로 표시한다. 개발값 +29.1 [+27.0, +31.2]는 아직 [커밋 필요] 상태다.
9. **서지 확인**: v3 REL 작성 메모 (1)–(6)을 원문과 대조한다(Exomiser 5,213증례의 출처, RareBench 증례 수, 이름이 같은 MedRAG 두 연구 등). Hoehndorf 2015는 게재본 수치("over 6,000", DO 질환 클래스 6,220개)를 쓴다.

### 0.4 결과 전환 방지 장치

- 설계 E의 주 목표 **E0 = E-T1 + E-T2(S-llm 비교)**를 네 곳에 그대로 둔다: 방법 3.6, 초록의 방법 문장, 초록 결과의 첫 문장, 표 6의 첫 행.
- 결과 절 첫머리(4.1)에는 D와 E의 **모든 사전 커밋 판정을 시간순으로 한 표(표 6)**에 둔다. 충족과 미달을 같은 표에 넣는다.
- 본문은 그 뒤 H1 → H2 → H3 → H4·음성 결과 → 제한·레버 → 출처 순으로 판정을 다시 묶는다. 각 절은 표 6의 행 번호를 가리킨다.
- E-T3는 매번 "사전 커밋한 7개 판정 가운데 부 목표"라고 적는다.
- 확증 이후 분석(P0, M1, M2, V1, P1-3)은 별도 패널에 결정 규칙, 커밋 해시와 함께 둔다. 지위는 [사후] 또는 [개발]로 표시한다.

## 1. 제목

- **국문(주안)**: 공개 문헌으로 다시 만든 출처 보존 질환–소견 그래프의 진단 지식 계층 평가: 같은 랭커에서 같은 문헌 BM25·큐레이션 주석과 비교한 봉인 확증과 구축 비용
- **영문(주안)**: *A provenance-preserving disease–finding graph rebuilt from public literature as a diagnostic knowledge layer: same-ranker comparison with same-corpus BM25 and curated annotations, sealed-set confirmation, and build cost*
- **대안(짧은 판)**
  - 국문: 공개 문헌 질환–소견 그래프가 진단 지식 계층으로 쓰이는 범위와 경계: 같은 랭커 비교와 봉인 확증
  - 영문: *Where a public-literature disease–finding graph serves as a diagnostic knowledge layer, and where it does not: a same-ranker comparison with sealed confirmation*
- **쓰지 않는 제목**
  - "진단 지식원으로 쓸 만한가?" 같은 예/아니오 질문형: 독자가 "예"를 기대하게 되는데, 절대 정확도 목표는 두 번 미달했다(D T2, E-T4).
  - "보완한다(complements)": M1 결정 규칙을 통과하지 못했다(`pilot/cache/v3/framing/m1/stats.json`).
  - v3의 추출 방식 중심 제목: 이 원고의 주 질문이 아니다.
- **결정 근거**(검토 문서 5.2 결정 흐름)
  - M1이 미충족이므로 "M1 실패" 행을 따른다. 제목은 유지하고, "보완"은 쓰지 않으며, 오라클 합집합은 보충자료에만 둔다.
  - P0-5 SemMedDB의 개발 매크로 Top-10은 23.20으로 S-dict 42.88보다 낮다. 그래서 §9.32 규칙에 따라 "공개 규칙 기반 자원이 같거나 높다"는 쓰지 않는다.
  - 다만 흔한 질환 두 세트의 S-dict − SemMedDB 군집 CI가 DDXPlus에서 0을 포함한다. 이는 5.1 #1의 "그 밖" 행에 해당하므로, H2의 우세 문장은 HPOA·PrimeKG·MeSH 대비로만 쓴다.

## 2. 한 문장 주장 (초록 결론과 6장 결론에 같은 문장으로 둔다)

> 공개 문헌으로 다시 만든 출처 보존 질환–소견 그래프는 큐레이션 주석을 대체하지 않는다. 그러나 같은 1-홉 랭커에서 두 봉인 세트 모두 같은 문헌 BM25보다 Top-10이 높았다. HPO 주석이 비우거나 얇게 둔 질환 공간도 다뤘다. 또 LLM 없는 사전 경로로 CPU 약 0.45시간에 다시 만들 수 있었다(문헌 수집 시간 제외).

바로 뒤에 반드시 둔다: "흔한 질환 정확도는 실행 전에 커밋한 목표에 미달했다(DDXPlus-E Top-1 12.4%, 목표 18%)."

## 7. 쓰지 않는 문장 (원고 점검표)

| 쓰지 않는 문장 | 이유 / 대신 쓸 문장 |
|---|---|
| "큐레이션을 대체한다", "희귀질환에서 경쟁력 있다" | 출판 증례 세트에서 36–43%p 낮다 |
| "큐레이션을 보완한다", "비어 있는 곳을 채운다", "결합하면 높아진다" | M1을 충족하지 못했다. "HPOA가 비우거나 얇게 둔 공간을 다뤘다"까지만 쓴다 |
| "흔한 질환에서 큐레이션보다 높다"(주어 없이) | 비교 대상이 희귀질환 자원이다. 주어는 늘 "같은 1-홉 랭커의 HPOA"로 쓴다. SemMedDB 대비로는 쓰지 않는다 |
| "텍스트 검색보다 높다" | 비교한 것은 BM25뿐이다 |
| "D 미달에서 E 충족으로 바뀌었다", "그래프가 BM25를 따라잡아 넘었다" | 세트, 기준, BM25 값이 다르다. 대신 "문헌을 늘리면 BM25는 희석되었고 그래프는 그렇지 않았다" |
| "1 CPU-h 안에 공개 문헌만으로 만든다", "흔한 질환에서는 사전 경로로 충분했다" | 수집 시간, UMLS, genes_to_disease가 빠진 표현이다. 사전 그래프도 Top-1 목표에 미달했다 |
| "LLM 추출이 필요하다", "사전 그래프가 LLM 그래프보다 낫다"(한정어 없이) | 판정 규칙, 입력 구조, 세트의 질환 영역에 달렸다 |
| "LLM의 역할은 선택이다"(측정처럼) | 해석으로만 쓴다 |
| "LOPO를 걸면 따라잡는다", 희귀 매크로 "LOPO 후 +2.70" | LOPO는 Phenopacket-store에서만 완전하다 |
| "새 질환을 먼저 따라잡는다" | 미래·신규 질환에서 2.2% 이하였다 |
| "간선이 정확하다", "출처가 있으므로 신뢰할 수 있다", "출처 연결은 새로운 기여", "최초", "비교할 자원이 없다", "세 요소를 모두 갖춘 연구를 찾지 못했다" | SemMedDB, PubCaseFinder, ChronoMedKG가 있다. 출처는 추적 가능성이다 |
| "판을 거듭할수록 나아졌다" | Top-1은 오르지 않았다(SymCat-E −0.8) |
| "7개 판정이 모두 예상과 일치해 예측이 정확했다" | 대신 "판정 기준과 예상을 실행 전에 커밋했고, 결과는 예상과 같았다" |
| "사전 등록", "Registered Report", "사전 지정" | 대신 "실행 전에 커밋한"(로컬 커밋 시각) |
| "같은 동결 랭커" | 대신 "같은 랭커 코드, 지식원별로 조정한 설정" |
| "질환 군집 CI가 다른 질환으로의 일반화를 보인다" | 같은 질환 집합 안의 변동만 반영한다 |
| "재현율이 정밀도보다 6배 큰 지렛대", "문헌 그래프 ≈ HPOA 재현율 15% + 오류 64%" | 철회한 감사의 오류 구성에 기댄 시뮬레이션이다 |
| 그래프 DB만 할 수 있다는 문장, RDB·벡터 DB와의 우열 | 저장 방식은 구현 선택이다 |
