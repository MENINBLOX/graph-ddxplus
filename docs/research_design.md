# 연구 설계 (v1, 2026-10-03)

> 이 문서가 연구의 기준이다. 이전 설계(속성 중심, 닫힌 후보 집합, 테스트 벤치마크로 설정 선택)는 폐기한다.
> 결정이 바뀌면 이 문서를 먼저 고치고, 그다음 코드를 고친다.

## 0. 한 문장 정의
저사양 LLM(RTX 4090 1장)으로 공개 문헌에서 정보추출한 그래프 DB 위에서, 추론 시점 LLM 없이,
모든 판단의 근거 문헌을 식별할 수 있는 감별진단을 수행하고, 이를 여러 진단 벤치마크로 검증한다.

## 1. 연구 질문
| RQ | 질문 | 1차 근거 |
|---|---|---|
| RQ1 | 문헌 IE로 만든 그래프가 추론 시점 LLM 없이 열린 후보 집합에서 감별진단을 할 수 있는가 | 벤치마크별 Top-1/3/10 |
| RQ2 | 그래프 기반 다단계 감별(다음 확인 소견 선택 → 재감별)이 확인 소견 수 대비 정확도를 높이는가 | 모의 문진의 정확도–IL 관계 |
| RQ3 | 진단 근거를 원 문헌(PMID/PMCID, 문장)까지 식별할 수 있는가 | 출처 연결률, 표본 감사 정밀도 |
| RQ4 | 진단 정확도는 IE의 차이를 반영하는가 (간접 검증) | 알고리즘 고정·IE 변경 시 정확도 차이 |

## 3. 경계 (Allowed / Forbidden)
원칙: **점수에 영향을 주는 정보는 (a) 공개 문헌 IE 결과, (b) 개념 어휘·계층(질환–증상 관계가 아닌 것), (c) 평가 대상 환자 본인의 입력뿐이다.**

| 자원 / 행위 | 판정 | 비고 |
|---|---|---|
| 공개 문헌(PubMed 초록, PMC OA 전문, NCBI Bookshelf 등) IE 결과 | 허용 | 출처 ID 보존 필수 |
| 개념 어휘·계층·동의어(UMLS, HPO 온톨로지 구조, MONDO 계층 등) | 허용 | 질환–표현형 간선이 아닌 개념–개념 관계만 |
| 벤치마크 근거 코드 → 표준 개념 크로스워크 | 허용 | 어휘 사상. 방법·코드 공개 |
| 질환–표현형 주석(HPO `phenotype.hpoa`, Orphanet, OMIM clinical synopsis) | **금지** | |
| 벤치마크가 배포하는 질환–증상 정보(DDXPlus 조건 파일의 증상 목록, SymCat 빈도) | **금지** | 사후 분석 전용 가능 여부도 별도 판단 |
| 벤치마크 학습 라벨로 학습·가중치 조정 | **금지** | |
| 벤치마크 환자 집단 통계(소견 보고 빈도 등)를 점수에 사용 | **금지** | 이전 "부재 근거" 빈도 가중은 폐기 |
| 벤치마크 정답 질환 목록을 후보 공간으로 사용 | **금지** (D3) | 평가 시 정답 대조에만 사용 |
| IE 대상 질환을 벤치마크 정답 기준으로 고르거나 더 깊게 수집 | **금지** | 질환 목록·수집 깊이는 온톨로지 기준으로 균일 |
| 벤치마크 환자의 원출처 문헌(증례보고) | **코퍼스에서 제외** | PMID 기준 제외, 겹침 수치 보고 |
| 설정·프롬프트 선택에 시험 데이터 사용 | **금지** | §5 프로토콜 |

## 4. 지표
- 1차: Top-1, Top-3, Top-10 (전 벤치마크 공통; RareBench의 Recall@k와 동일 정의).
- RQ2: IL(확인한 소견 수)과 최종진단 정확도. DDXPlus 원 논문 지표(GTPA@1, DDR/DDP/DDF1, IL)는 DDXPlus에 한해 병기.
- RQ3: 출처 연결률, 표본 감사 정밀도.
- 통계: 환자 단위 부트스트랩 95% CI, 조건 비교는 paired bootstrap, 다중 비교 보정.

## 5. 설정 선택 프로토콜 (D12, 2026-10-03 확정)
- 설정·프롬프트·임계값 등 모든 선택은 **벤치마크가 공식 배포한 validation 분할에서만** 한다.
- 공식 validation 분할이 없는 벤치마크는 선택에 전혀 쓰지 않는 **순수 시험용**이다.
- 선택이 끝나면 설정을 동결하고, 그 뒤에 시험 분할을 처음 평가한다. 동결 시점(커밋)을 기록한다.
- 결과적으로 선택은 DDXPlus `validate`에 의존할 가능성이 크다. 흔한 질환·문진 코드에 맞춰진 설정이
  희귀질환 벤치마크로 전이되는지가 그대로 일반화 검증이 되며, 이 의존성은 논문에 명시한다.

## 6. 다단계 감별 (RQ2) 프로토콜 초안
1. 초기 입력: 벤치마크가 주는 초기 근거(DDXPlus는 주소; 그 외는 무작위가 아닌 결정론적 규칙의 일부 소견).
2. 감별: 열린 집합 전체 순위.
3. 다음 확인 소견 선택: 상위 후보 부분그래프에서 결정론적 기준(정보이득 등)으로 1개 선택.
4. 응답: 환자 기록에 있으면 양성, 없으면 음성.
5. 종료 규칙(미결) 후 최종진단 = 마지막 순위.
위험: HPO 기반 벤치마크는 "기록 없음 ≠ 음성"이라 음성 응답의 타당성이 약함 → 벤치마크별로 RQ2 적용 가능성을 먼저 판정.
