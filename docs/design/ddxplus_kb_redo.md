# DDXPlus 공개 KB 탐문 연구 설계 (2026-10-22)

> 상태: 개발 전 확정본. 이 문서의 후보 설정, 선택 목적함수, 판정 규칙, 예상값은 개발과 평가보다 먼저 커밋한다.
> 근거 검토: `docs/v1_ddxplus_review_2026-10-21.md`. 이전 판(v1, `archive/v1_ddxplus/`)의 원고와 코드는 쓰지 않는다.
> 출판된 적 없는 이전 판이 공식 test를 개발에 썼다는 사실은 원고에 공개한다.

## Context and Scope

DDXPlus(Fansi Tchango 외, NeurIPS 2022 Datasets and Benchmarks)는 49개 질환의 합성 환자 약 130만 명을 담은 대화형 감별진단 벤치마크다.
환자는 공개된 지식 파일 `release_conditions.json`(질환별 증상·병력 목록)과 `release_evidences.json`(evidence 정의)으로 생성되었다.
대화형 과제에서 에이전트는 초기 evidence 1개를 받고, evidence를 하나씩 물어 감별진단을 낸다. 문헌의 에이전트(AARLC, BASD, CASANDE,
LLM 에이전트 등)는 이 과제를 환자 데이터로 학습하거나 LLM 지식으로 푼다.

이 연구는 그 공개 지식 파일만으로 이 과제가 얼마나 풀리는지 잰다. 공개 지식 파일은 환자 생성기의 지지집합을 그대로 담으므로,
이 측정은 새 진단 방법이 아니라 벤치마크가 무엇을 재는지에 대한 측정이다.

**용어**
- **멤버십 KB**: `release_conditions.json`의 질환 → evidence 목록. 확률 없이 포함 여부만 있다(49 × 223 이진 행렬).
- **지지집합**: 생성기가 한 질환에서 만들 수 있는 evidence의 집합.
- **IL**: 환자 1명당 수집한 evidence 수. 초기 evidence를 포함한다(DDXPlus 식 4).
- **GTPA@k**: 정답 질환이 예측 상위 k 안에 드는 환자의 비율. **동점 반영 GTPA@1**은 1위가 k개 질환의 동점이고 정답이 그 안에 있으면 1/k점을 준다.
- **EIG**: 한 질문의 답이 질환 사후분포의 엔트로피를 평균적으로 줄이는 양.

## Goals and Non-Goals

**Goals**
- RQ1: 멤버십 KB만 알고 환자 데이터로 학습하지 않을 때, 표준 프로토콜(초기 evidence 1개, |T| ≤ 30)에서 Bayes 탐문(P1)의 GTPA@1·@3, GTPA, IL은 얼마인가. 질문 예산 0–29별 정확도 곡선은 어떤가.
- RQ2: 같은 코드에서 우도표만 train 빈도로 바꾼 빈도 Bayes(P2)는 정확도 상한과 질문 효율에서 무엇이 다른가.
- RQ3: 정확도는 KB의 어느 부분에서 오는가(양성·음성 응답, 지지집합 배제의 강도, 질문 단위, 질문 선택 방식, 값 정보, 사전확률).
- 데이터셋 성질: validation, H1, H2에서 KB 위반 환자 수와 집합 포함 유일성 비율을 보고한다.

**Non-Goals**
- 새 질문 선택 방법을 제안하지 않는다(EIG 탐욕 선택은 표준이다).
- 임상 적용, 실제 환자로의 일반화, LLM 에이전트와 동급이라는 주장은 하지 않는다.
- 이전 판(v1)의 규칙을 개선하지 않는다. 부록에서 재현만 한다.

## Design

### 1. 데이터 역할

| 세트 | 행 | 용도 |
|---|---:|---|
| validation | 132,448 | 모든 개발, 설정 선택, ablation, 환자별 실패 분석 |
| train − H2 | 891,073 | P2와 참조점의 빈도 추정(P(d), P(e=v∣d), 나이·성별 조건부). P1은 쓰지 않는다 |
| **H2** (train hold-out) | 134,529 | 동결 후 1회 평가. train 1,025,602행에서 `random.Random(20261022).sample`로 뽑는다 |
| **H1** (공식 test − 9,000행) | 125,529 | 동결 후 1회 평가. 문헌 비교용. 빼는 9,000행은 이전 연구(v2)가 쓴 행이다: 개발 표본(seed 0, 3,000), 설계 D 확증(seed 101, 3,000), 설계 E 확증(seed 202, 3,000). 집계값만 보고한다 |

- 매니페스트(`paper1/manifests/H1.json`, `H2.json`: 행 번호, 원시 행 sha256, CSV sha256, seed)를 개발 전에 커밋하고 원격에 push한다.
- 로더는 플래그(`DDXKB_UNSEAL=1`) 없이는 H1·H2 행을 내주지 않고, 개발 코드는 validation과 train − H2만 읽는다.
- KB 원본은 `data/ddxplus/20043374.zip` 안의 `release_conditions.json`·`release_evidences.json`(프랑스어 코드판)이다. 환자 CSV의 코드와 그대로 맞는다.

### 2. 상호작용 프로토콜

- 시작 입력은 환자의 `INITIAL_EVIDENCE` 1개다. P1은 나이·성별을 쓰지 않는다(KB에 없다). P2는 나이·성별을 쓰는 판과 쓰지 않는 판을 둔다.
- 질문 단위는 DDXPlus evidence 코드 1개다(223개). CUI로 묶지 않는다. 같은 질문을 두 번 묻지 않는다.
- 응답: 이진 evidence는 환자 레코드에 있으면 "예". 범주형·다중선택은 값을 모두 드러낸다. 값이 `default_value`이면 음성이다.
  이진 응답 모드에서는 "기본값이 아닌 값이 있는가"만 본다. 값 단위 응답 모드는 P2와 A6에서만 쓴다.
- 종료는 정책의 종료 규칙과 |T| = 30(초기 evidence 포함) 가운데 먼저 오는 쪽이다.
- 정렬과 동점은 KB 파일의 질환·evidence 순서를 2차 키로 써서 결정적으로 처리한다. 예외가 난 환자는 오답으로 세고 건수를 보고한다.

### 3. 정책, 기준선, 절제

**정책** (같은 코드, 우도표만 다르다)
- **P1 KB-Bayes + EIG**: 목록 안이면 P(e=예∣d) = α, 밖이면 ε. 균등 사전확률. EIG 탐욕 선택. 사후 최대값 ≥ τ 또는 |T| = 30에서 종료.
- **P2 빈도 Bayes + EIG**: P(d)와 P(e=v∣d)를 train − H2 빈도로 추정(Laplace 평활 λ). 범주형은 값별, 다중선택은 선택지별 우도.
  판 네 가지: 이진/값 단위 응답 × 나이·성별 미사용/사용.

**기준선과 참조점**
- B0: 질문 0개. train 최빈 질환, 그리고 초기 evidence만으로 낸 P1 사후 1위(동점 반영).
- B1: 전체 프로필 참조점(질문 비용 0): 집합 포함 검사, P1 사후, P2(NB). "상한"이라 부르지 않는다.
- B2: 무작위 질문(KB 후보 안), 순위와 종료는 P1과 같다. seed 5개(`(seed, 행 번호)`로 생성).
- B6: KB 없는 질문 선택(train 전역 빈도순), 순위는 P1·P2.

**절제** (validation만, 고정 예산 5/10/15/20/29와 자체 종료에서)
- A1 양성만 / 음성만 / 둘 다, A2 균등 대 train 사전확률, A3 ε 크기, A4 질문 단위(코드 / CUI로 묶음 / 하위속성 제거),
  A5 질문 선택(EIG / 무작위 / coverage 순), A6 이진 대 값 단위 응답.

**부록: 이전 판(v1) 재현** — v1 규칙을 결정적 판으로 이식해 validation에서 CUI 단위, 코드 단위, 하위속성 제거, trav1 버그 on/off,
동점 seed 10개 범위를 보고한다. 원 DB가 없으므로 보고값과의 차이는 추정으로 쓴다.

### 4. 지표와 통계

- 지표: IL(평균, 중앙값, 95백분위, 상한 도달 비율), 동점 반영 GTPA@1(주), 고정 순서 GTPA@1(보조), GTPA@3·@5, GTPA, DDR·DDP·DDF1(0.01 후처리),
  PER(초기 evidence 제외). 멤버십 정책의 감별 분포는 "정규화 사후 > 0.01"의 고정 규칙 하나로 내고 튜닝하지 않는다.
- 통계: GTPA@k에 Wilson 95% CI, IL·DDF1·PER에 환자 단위 bootstrap(B = 2,000, seed 0) 95% CI. 같은 환자의 두 정책 비교는 GTPA@1에 정확 McNemar,
  IL 차이에 paired bootstrap. ANOVA는 쓰지 않는다. B2는 평균 ± SD와 범위.

### 5. 설정 선택과 동결

- 후보 공간(개발 전 고정):
  - P1: α ∈ {0.3, 0.5, 0.7}, ε ∈ {1e-2, 1e-3, 1e-4}, τ ∈ {0.9, 0.95, 0.99} — 27개.
  - P2(판마다): λ ∈ {0.5, 1.0}, τ ∈ {0.9, 0.95, 0.99, 0.999} — 8개.
- 목적함수: validation의 동점 반영 GTPA@1 최대(|T| ≤ 30). 같으면(소수 둘째 자리) 평균 IL이 작은 쪽, 그래도 같으면 위 나열 순서의 앞쪽.
- 시도한 설정은 모두 `paper1/outputs/dev/configs_tried.jsonl`에 남기고 커밋한다.
- 동결: `paper1/configs/protocol_frozen.yaml`에 모든 정책·기준선의 설정, 예산 목록, 매니페스트 해시를 넣어 커밋하고 push한다.
- 평가 실행기는 작업 트리가 깨끗하고 설정 해시가 동결값과 같을 때만 돈다. H1과 H2의 모든 정책·기준선·예산 곡선을 한 번에 내고,
  환자별 JSONL(gzip)과 요약 JSON에 입력 sha256과 커밋 해시를 기록한다. 출력은 `paper1/outputs/`(git 추적)에 둔다.
- 평가 뒤 버그를 찾으면 고쳐서 다시 돌리고, 두 결과를 모두 부록에 적는다.

## Alternatives Considered

- **Neo4j·UMLS 그래프 유지**: 정보만 잃는다(223개 코드 → 188개 CUI, 하위속성 14개 소실). 측정 대상이 KB의 내용이므로 메모리 행렬로 충분하다.
- **공식 test 전체를 평가에 쓰기**: 9,000행은 이전 연구가 열었다. 문헌 비교성은 125,529행에서도 유지된다(n 6.7% 감소, CI ±0.2%p 수준).
- **H2 없이 H1만 평가**: 이전 판이 test를 개발에 썼으므로, 개발에 쓰지 않은 추가 평가 세트를 둔다.

## Cross-cutting Concerns

- 재현성: 모든 정렬에 2차 키, 무작위성은 B2에만, `hash()` 금지, 입력 sha256 기록.
- 데이터: DDXPlus는 CC-BY 4.0. 원시 CSV는 저장소에 넣지 않고 매니페스트와 해시만 커밋한다.
- 연구 윤리: 이전 판이 test를 개발에 썼다는 사실과 이 연구가 그 판의 수치를 재현하지 못했다는 사실을 공개한다.

## 개발 전 보완 (2026-10-22, 구현 중 드러난 미정 사항, 전체 개발 실행 전 커밋)

구현과 코드 검토에서 설계가 정하지 않은 항목이 드러났다. 전체 validation 개발 실행 전에 아래로 고정한다. 코드의 해당 상수와 정의는 괄호 안에 있다.

1. **종료 규칙 추가**: 남은 질문의 최대 EIG가 1e-6 nats 미만이면 종료한다(`protocol.MIN_GAIN`, 튜닝하지 않음). KB에는 다른 질환 목록에 통째로
   포함되는 목록이 있다(안정형 협심증 ⊂ 불안정형, 만성 ⊂ 급성 부비동염). 그런 환자는 τ에 닿지 못하고 |T| = 30까지 정보 없는 질문을 하게 된다.
   검토 때 원형 스크립트도 이 규칙을 썼다.
2. **예상값 갱신**(§6, 같은 20,000명 표본, KB 파일 순서 동점, 위 종료 규칙 포함): P1(α .5, ε 1e-3, τ .99) GTPA@1 98.40%, IL 11.65
   (원형의 이름순 동점이면 98.39%, 11.46). P2 이진(λ .5): τ .99에서 98.52%, IL 7.25; τ .999에서 98.84%, IL 8.66. J1·J2의 예상 판정은 그대로다.
3. **P2의 나이·성별**: 사전확률 P(d ∣ 나이 구간, 성별)에만 넣고 우도는 질환별로 둔다. 나이 구간 경계는 (2, 5, 8, 10, 18, 30, 33, 45, 60, 75)이고,
   train − H2에서 질환별 나이 범위를 보고 정했다(`policies.bayes.AGE_BIN_EDGES`). validation은 보지 않았다.
4. **값 단위 응답**: 범주형은 기본값을 포함한 K개 값에 대한 정확한 EIG를 쓴다. 다중선택은 선택지별 독립 Bernoulli의 곱을 우도로 쓰고,
   질문 효용은 선택지별 EIG의 최댓값이다(CASANDE B.3). Laplace λ는 성분의 결과마다 더하고 P(d)에도 같은 λ를 쓴다.
5. **A4 질문 단위**는 네 판이다: 코드(223), v1의 CUI 공간(188, CUI가 없는 19개 코드는 물을 수 없음), CUI로 묶되 CUI 없는 코드는 그대로 둔 판(207),
   하위속성 제거(209). 묶음 효과와 코드 삭제 효과를 떼어 보기 위해서다.
6. **절제·기준선 상수**: A1은 한 극성의 응답을 묻고 기록하되 사후확률에는 반영하지 않는다(질문 선택은 그대로). 음성만 판은 초기 evidence도
   반영하지 않는다. A2의 train 사전확률은 Laplace λ = 1.0. A3의 ε는 {1e-1, 1e-2, 1e-3, 1e-4, 1e-6, 1e-9}이고 α·τ는 선택값으로 고정한다.

   `e10_e11`, `cancer_méta`, `j17_j18`, `j44_j42`, `fam_j45`의 `code_question`(`e10, e11` 등)은 카탈로그에 없는 문자열(프랑스어판 오타)이다.
   이들은 독립 질문으로 둔다(CASANDE와 같다). 주 프로토콜은 계층을 쓰지 않고, 계층 민감도와 A4만 쓴다.
4. **암묵 응답**(계층 민감도): CASANDE `_set_symptom_to_observation`처럼 두 방향으로 채운다. 부모가 음성이면 아직 모르는 자식을 모두
   음성(기본값)으로 채우고, 자식이 양성이면 아직 모르는 부모를 양성으로 채운다. 보완 2 §3의 괄호는 앞의 방향만 적었다.
   채운 답은 턴을 쓰지 않으므로 IL에 넣지 않고, 다시 물을 수도 없다. 음성 자식과 양성 부모는 아무것도 채우지 않는다.
   기록이 계층과 어긋나는 환자(부모 없이 양성인 자식)는, 그 부모나 자식을 물어 채울 답이 기록과 어긋날 때 예외가 나 실패로 센다.
   둘 다 묻지 않으면 실패가 아니다(validation에는 그런 환자가 0명이다).
   - 사후 처리: 채운 답은 물었을 때 받는 답과 같은 우도로 사후에 곱한다. 부모 음성과 자식 음성은 한 사실이므로 최대 8번(lesions_peau와 자식 7)
     곱해지는 이중 계산이 생긴다. 이 이중 계산은 주 프로토콜에서 같은 질문들을 차례로 물어도 똑같이 생긴다. 그래서 민감도가 바꾸는 것은
     '계층 답을 턴 없이 받는 효과' 하나다. 이 점을 한계로 적는다.
   - 점검 중 측정: validation 앞 4,000행, P1 α .5·ε 1e-3·τ .99에서 결과는 다음과 같다.

     | 규칙 | GTPA@1 | IL |
     |---|---:|---:|
     | 주 프로토콜 | 98.50% | 11.63 |
     | 이 규칙 | 98.51% | 11.16 |
     | 채운 답을 사후에서 뺀 규칙 | 98.82% | 11.57 |

     정확도가 높은 대안을 고르지 않고 원칙대로 둔다.
   - 질문 선택과 PER: EIG는 그 질문 자신의 답만 세고, 함께 채워질 답은 내다보지 않는다. 채운 답은 물은 질문이 아니므로 PER 두 정의의
     분자에 들어가지 않는다(분모는 환자의 양성 evidence 전체).
5. **계층 민감도의 범위**: P1과 P2 네 판을 주 프로토콜에서 고른 설정 그대로(재선택 없이) 암묵 응답으로 다시 돌린다.
   validation과 T(부분집합 포함)에서 낸다. 각 판은 같은 행에서 P1 주 실행, 그리고 자기 주 실행과 비교한다. 비교는 예산과 종료 시점에서 하고,
   McNemar(고정 순서 GTPA@1)와 IL 차이 paired bootstrap을 쓴다. 기준선과 B-BED는 돌리지 않고, 판정에 쓰지 않는다.
6. **동점 허용**:
   - EIG: 최대 EIG와의 차이가 1e-12 nats 이하인 열린 질문을 동점으로 보고, 그 가운데 KB 순서의 첫 질문을 고른다(1차와 같다).
   - 사후확률: 상대오차 1e-9 이내를 동점으로 본다(`metrics.TIE_RTOL`). 동점 반영·고정 순서 열에만 쓰고 공식 열(F.1)에는 쓰지 않는다.
   - 공통: 두 값 모두 반올림 차이가 질문이나 순위를 바꾸지 않게 하는 값이며, 튜닝하지 않는다.
7. **실패 환자**: 정책 실행이나 채점 중 예외가 나면 실패로 센다. B-BED의 사후 소멸도 포함한다.
   - 채점: 종료 시점과 모든 예산 지점에서 모든 지표를 0점으로 센다.
   - IL: 그 실행의 상한으로 센다(A.1).
   - 보고: 요약에 실패 수와 앞 20건의 오류를 적는다. v1 이식판의 실패 IL은 그 판의 최대 질문 수 + 1이다.
   - validation 현황: 실패를 일으킬 데이터 조건은 0건이다. 비이진·비양성 초기 evidence, KB 밖 질환, 계층 위반, 레코드 형식 오류
     (값이 붙은 이진 evidence, 값 없는 범주형·다중선택, 가능값 밖의 값, 값이 2개 이상인 범주형)가 모두 0건이다.

### C. 설정 선택 (§5, 보완 2 §4 보충)

1. **목적함수**: validation 전체에서 종료 시점의 동점 반영 GTPA@1을 본다. 이를 백분율로 바꿔 소수 둘째 자리로 반올림(Python `round`)한 값이
   큰 쪽을 고른다. 같으면 평균 IL(반올림하지 않음)이 작은 쪽, 그래도 같으면 나열 순서가 앞선 쪽이다. 나열 순서는 P1이 α, ε, τ의 곱이고
   τ가 가장 빨리 변한다(0–26). P2는 λ, τ의 곱이다(0–7).
2. **어느 줄로 고르는가**: 가장 최근의 전체 validation grid 실행이 그 실행에서 낸 원 격자 줄로만 고른다. 이전 실행의 줄은 시각·커밋과 함께
   `configs_tried.jsonl`에 남지만 선택에는 쓰지 않는다. 행 제한(`--limit`) 스모크 실행은 `paper1/outputs/v2/dev_limitN`에 쓰고, 동결하지 않는다.
3. **넓힌 격자**: 선택값이 목록 끝에 있는 매개변수만 그 끝 쪽으로 한 값을 더한다(`protocol.P1_WIDER`). 더하는 값은 다음과 같다.

   | 매개변수 | 앞 끝 | 뒤 끝 |
   |---|---|---|
   | α | 0.1 | 0.9 |
   | ε | 1e-1 | 1e-5 |
   | τ | 0.8(1 − τ를 두 배로) | 0.999 |

   - 평가: 늘린 목록들의 곱을 같은 행에서 평가한다. 원 27개를 포함하며, ε와 τ가 모두 뒤 끝이면 48개다. 새 설정만 grid `"wider"`로 기록한다.
   - 기록: 같은 목적함수로 넓힌 격자의 최선을 고른다(나열 순서는 넓힌 격자 기준). 그 최선과 원 선택과의 일치 여부를
     `selected.json`의 `P1.boundary`에 적는다.
   - 선택과 동결은 원 27개에서만 한다.
4. **재선택 효과**: 1차 선택 설정이 새 격자에 모두 들어 있다(P1 α .5·ε 1e-4·τ .99, P2 τ .999와 λ .5/.5/1.0/.5).
   그래서 validation에서는 `configs_tried.jsonl`의 그 줄과 새 선택을 나란히 적는다. 그 줄은 개정 상한(IL ≤ 31)에서 낸 값이고,
   P2는 여기에 새 지식(train 전체, 공식 나이 구간)이 더해진다. 점추정과 Wilson 구간만 있고 짝비교는 없다.
   T에서는 1차 설정을 따로 돌리지 않는다.

### D. 지식과 데이터 (보완 2 §2·§5 보충)

1. **train 사용 범위**: train 전체(1,025,602행, H2 포함)는 P2, B-BED 보조 판, B0 최빈 질환, B1 NB, B6 질문 순서,
   A2 사전확률(λ = 1.0), A6에 쓴다. train − H2(891,073행)는 I의 차이표에서 P2를 다시 돌릴 때만 쓴다. P1 본체는 train을 읽지 않는다.
2. **환자 파일**: `data/ddxplus/20043374.zip`(figshare 20043374 v14) 안의 `release_*_patients.zip`을 푼 CSV다. v9(2022-06-18)에서 교체된 판이다.
   sha256은 validate 000e632b…, train 1bb2376f…, test c44c346e…이다. train과 test는 동결 파일과 T 매니페스트가 고정한다.
   validation은 동결 파일이 sha256으로 고정하는 `selected.json`의 provenance가 고정한다.
3. **매니페스트**: `paper1/manifests/{T, T-dedup, T-streambench}.json`이다(bc18f0b에서 커밋·push). 담는 내용은 CSV 경로·sha256, 행 수,
   선택 규칙, 행 번호, rows_sha256이다. 행 번호는 헤더 다음 데이터 행을 0부터 센다. rows_sha256은 행 번호 오름차순으로 원시 줄과
   줄바꿈을 이어 붙인 것의 sha256이다. 부분집합은 T의 행만 가리키고, 매니페스트는 덮어쓰지 않는다.
4. **T-dedup**: 키는 (나이, 성별, 초기 evidence, 기록된 evidence 항목의 집합)이고, `data.input_key`가 만든다.
   - 키 구성: 항목은 CSV에 적힌 그대로의 `code` 또는 `code_@_value`이고, 기본값 항목도 포함한다. 나이는 CSV 문자열 그대로 쓰고,
     질환은 키에 넣지 않는다.
   - 결과: train 전체의 어느 행과도 키가 같지 않은 T 행 132,540행이다(1,989행, 1.48% 제외).
   - 참고: 같은 키로 validation은 1,808행(1.37%)이 train과 겹친다. 나이·성별·초기 evidence는 그대로 두고 항목 집합만
     값을 무시한 양성 코드 집합(기본값 항목 제외)으로 바꾸면 18,592행(14.04%)이 겹친다.
5. **T-streambench**:
   - 출처: HF `appier-ai-research/StreamBench` revision a387d5d86c4fab1b7cff724a3cdea0299a716b91의
     `ddxplus/test-00000-of-00001.parquet`(sha256 4bf0ef52…)에서 만든다.
   - 대응 규칙: StreamBench 각 행에 대해 T-dedup 키, 정답 질환, 정답 감별이 모두 같은 T 행을 짝으로 삼는다. 키의 나이는 StreamBench 값을
     `str()`로 바꾼 문자열이다. 감별은 (질환, 확률) 쌍을 정렬해 순서와 무관하게 비교하고, 확률은 float 정확 일치로 본다.
     영어 질환명은 KB의 `cond-name-eng`으로 대응시킨다.
   - 겹치는 행: 내용이 같은 T 행이 여럿이면 StreamBench 파일 순서대로 아직 배정되지 않은 가장 앞 행을 고른다(10행).
     B2는 행 번호로 난수를 만들므로 이 규칙이 그 행들의 B2 값을 정한다.
   - 결과: 1,764행이 모두 대응해야 부분집합을 쓰고, 아니면 '목록 없음'으로 봉인한다. 실제로 1,764행이 대응했고,
     그중 116행은 H1에서 뺀 9,000행에 속한다.
6. **데이터셋 성질**(목록 밖 양성 환자 수, 집합 포함 유일성 두 정의)은 validation과 T 전체에서 낸다. 부분집합으로는 자르지 않는다.
   H1·H2 값은 1차 결과를 인용한다.

### E. B-BED (보완 2 §6 보충·정정)

1. **지식원 두 판**을 같은 실행에서 돌린다.
   - (a) 주 판 `B-BED`: BED 저장소의 통계 파일 `ddxplus_bed_stats_4.json`(Casande-RL@5279013 `Baselines/BED/dataset/ddxplus/`)을 그대로 읽는다.
     복사본은 `paper1/reference/casande_bed/`에 있고, sha256 84e781b350800eb8a2087c5749e0d1eb07d81a4e8a50ddffcab3e06e70df533c를
     동결하며 평가 전에 검사한다. 사전확률, 질환별 관측 evidence, 이진·범주형 비율은 train 전체 집계와 비트 단위로 같다.
     다중선택만 기록당 값 하나로 셌다(BED 생성 코드에서 집합을 순회한 마지막 값).
   - (b) 보조 판 `B-BED-counted`: 같은 규칙을 train 전체에서 다시 세되, 다중선택은 값을 모두 센다.
   - 응답은 두 판 모두 E.4를 따른다. J3′는 (a)로만 판정한다. §7의 '`reference/`는 실행 경로가 아니다'에는 이 통계 파일이 예외다.
2. **후보 제한 기준은 train 관측이다**. BED 기본 설정에서는 `restrict_flag`가 참이다(`run_ddxplus.sh`가 `--no_patho_restriction`을 주지 않는다).
   - 정의: 질환이 evidence를 '안다'는 것은 통계 파일의 그 질환 findings에 그 evidence가 있다는 뜻이다. 범주형·다중선택은 통계를 만들 때
     목록 항목을 기본값으로 채우므로 목록과 같다. 이진은 train 기록에 한 번 이상 나온 것만 든다.
   - 목록과의 차이: 목록에서 이진 6쌍이 빠지고, 목록 밖 항목은 없다. 빠지는 6쌍은 Chagas–oedeme, Myocardite–irritable,
     국소 부종–dyspn·ww_dd·dyspn_noct, Sarcoïdose–lesions_peau다.
   - 적용: 초기 evidence로 시작하고, 이후 모든 양성 응답마다 교집합으로 다시 좁힌다. 질문 후보는 후보 질환이 아는 evidence 가운데
     아직 묻지 않은 것이다. 후보 밖 질환은 이미 우도가 0이므로, 제한은 탐색 범위만 줄인다.
   - validation 현황: 6쌍이 양성인 환자와, 초기 evidence가 정답 질환에 미관측인 환자는 모두 0명이다.
3. **미관측 처리** (§6의 '미관측 1e-7'을 정정한다):
   - 이진: 미관측 (질환, evidence) 쌍은 P = 0이다. 목록 밖 쌍 전부와 E.2의 6쌍이 여기에 든다. 양성 응답이면 그 질환은 배제되고,
     음성 응답이면 1이다.
   - 1e-7: 범주형·다중선택 선택지에만 쓴다. 질환의 train에 없는 선택지에는 통계 파일에 든 1e-7을 쓴다. 선택지 목록 밖 응답 값에는
     아는 질환에 1e-7, 모르는 질환에 0을 쓴다. 모르는 질환의 음성 응답에는 1 − 1e-7을 쓴다.
   - 평활은 없다.
4. **응답은 BED 시뮬레이터다**. §3의 오라클이 아니라 BED의 `eval_reset`·`eval_step`(bayesian_experimental_design_batch.py:148-244)을 따른다.
   - 양성·음성: 기록된 evidence는 값과 무관하게 양성이다(기록된 기본값 포함). 정답 질환이 아는 범주형·다중선택은 기록에 없어도
     기본값으로 채워 양성이다. 그래서 범주형·다중선택이 음성인 것은 기록에도 정답 질환 목록에도 없을 때뿐이다. 이진은 기록에 없으면 음성이다.
     validation에서는 정답 질환 목록의 범주형·다중선택이 기본값까지 모두 기록되어 있다(빠진 경우 0건, 목록 밖 기록 0건). 그래서 채우기 규칙은
     실제로 작동하지 않는다.
   - 드러나는 정보: 목록 소속은 기록된 기본값을 양성으로 읽는 데서 드러난다. validation 앞 3,000명에서 B-BED가 물은 범주형·다중선택
     6,930개 가운데 1,310개는 BED 시뮬레이터로는 양성이지만 §3 규칙으로는 음성이었다. 모두 기본값이 기록된 응답이다. §3 규칙의 음성은
     모두 4,191개이고, 나머지 2,881개는 두 규칙에서 모두 음성이다. 환자 38.6%가 앞의 1,310개 같은 응답을 1개 이상 받았다.
   - 다중선택: 양성이면 기록 순서의 마지막 값 하나만 싣는다(`eval_reset`이 값을 이름 키로 찾고 인덱스 키로 저장하기 때문이다).
     그 값이 BED 선택지 목록 밖이면 선택지 −1이 된다. validation에서 이런 기록은 douleurxx_endroitducorps 911건,
     lesions_peau_endroitducorps 1,867건, oedeme_endroitducorps 879건이다.
   - 정수 기본값: 기본값이 정수 0인 범주형 6개(douleurxx_soudain·_intens·_precis, lesions_peau_intens·_elevee·_prurit)는
     기본 선택지 조회가 실패해 −1이 된다. 음성 응답은 모든 질환에 1 − 1e-7이 되어 정보가 없다. 기본값으로 채운 양성 응답은
     아는 질환에 1e-7, 모르는 질환에 0이 되지만, 채우기가 일어나지 않으므로 validation에서는 생기지 않는다. 기록된 '0'은 BED 선택지에
     있는 값이라 그 비율을 쓴다.
   - 결론: 모두 BED 코드의 동작이며 재현을 위해 그대로 둔다. B-BED와 P2(값 단위)의 같은 행 비교는 이 응답 규칙 차이를 포함한 비교로 보고한다.
5. **효용과 종료**: `run_ddxplus.sh` 설정을 따른다(BED_BATCH, KL 효용, 탐색 깊이 1, 임계 0.01, 30문항).
   - 효용: Σ_o P(o) Σ_d q′(d∣o)[ln(q′(d∣o) + ε) − ln(q(d) + ε)]이고, ε는 float64 machine epsilon이다.
   - 결과 집합: 이진은 예·아니오를 쓴다. 범주형은 BED 선택지 각각의 양성 결과만 쓴다. 다중선택은 선택지마다 (있음, 없음) 두 결과로
     효용을 구하고 그 최댓값을 쓴다.
   - 종료: 최대 효용이 0.01 이상이면 묻고, 0.01 미만이거나 양의 효용이 없으면 멈춘다. 상한은 초기 evidence 뒤 30문항이다(IL ≤ 31).
   - 동점: 최대 효용과의 차가 1e-14 이하인 질문 가운데 KB 순서의 첫 질문을 묻는다. 원 코드는 정수 집합의 순회 순서에서
     처음으로 '더 큰' 효용을 고르므로, 반올림 수준의 동점에서만 다른 질문을 할 수 있다.
6. **채점**은 종료 시점의 정규화 사후(49개 질환)로 한다. BED의 마지막 진단 분포와 같다. 나이와 성별은 쓰지 않는다.
7. **이식 검증**:
   - 원 코드 실행: BED 원 코드(Casande-RL@5279013 `BEDBatch.batch_run`, 같은 통계 파일)를 `run_ddxplus.sh` 인자로 validation 전체에 돌렸다
     (`paper1/reference/casande_bed/run_original.py`). 환경은 Python 3.12, numpy 1.26.4, pandas 2.2.3, tqdm 4.66.5다. 원 코드 수정은
     numpy가 없앤 `np.float` 별칭을 `float`으로 되살린 것 하나다.
   - 전체 비교:

     | | GTPA@1 | 평균 IL |
     |---|---:|---:|
     | 원 코드 | 99.442% | 5.472 |
     | 이식판 주 판(공식·동점 반영 같음) | 99.442% | 5.476 |

     공식 GTPA@1은 모든 환자에서 같다.
   - 고정 자료와 테스트: 행 0–999의 원 코드 출력(질문열, IL, GTPA@1)을 `tests/fixtures/bed_original_validate_head.json.gz`로 두고,
     테스트가 매번 대조한다. 통과 기준은 세 가지다. 공식 GTPA@1이 모든 환자에서 같아야 한다. 질문열 차이는 첫 분기점의 효용 차가
     1e-14 이하일 때만 생겨야 한다. 질문열이 다른 환자가 5% 이하여야 한다(현재 질문열 28명, IL 5명이 다르다).
   - 원 코드는 공식 test에 돌리지 않는다.
8. **예산 곡선**은 BED에 없는 이 연구의 확장이다. 종료 뒤에도 효용이 최대인 질문을 계속 묻는다. 양의 효용이 없으면 더 묻지 않고,
   이후 예산에는 그때의 사후를 쓴다. BED 규칙과 같은 것은 종료 시점 값뿐이다.

### F. 지표 (보완 2 §7 보충)

1. **공식 GTPA@k**는 공식 코드 식 그대로다.
   - 계산: 사후를 공식 코드의 질환 색인 순서로 놓는다. 그 순서는 `release_conditions.json` 키의 Python 문자열 정렬이다
     (CASANDE·DDXPlus `load_and_check_data`의 `sorted(data.keys())`). `np.argsort(pred)[::-1][:k]`에 정답이 있고
     pred[정답] > 0.01이면 1점이다.
   - 동점: 정확한 동점은 2차 키 없이 numpy 정렬 커널의 결과를 그대로 쓴다. 그래서 이 열만 'KB 순서 2차 키' 원칙의 예외다.
   - 환경 고정: 위 이유로 개발과 평가는 같은 Python·numpy·pandas 판과 같은 numpy SIMD 디스패치에서만 돈다(동결 파일 `environment`, 다르면 거부).
     질환 색인 순서는 동결 상수이고(`official_disease_order`), BED 통계 파일의 질환 순서와도 같다.
2. **GTPA@3·@5도 두 열**이다. 두 열 모두 Wilson CI를 붙인다.
   - 동점 반영 열: min(1, max(0, (k − 동점이 아니면서 정답보다 큰 질환 수) / 정답을 포함해 정답과 동점인 질환 수))이다.
     동점은 B.6의 상대오차 1e-9 기준이다. 정답 질량이 0.01 이하이면 0이다.
   - 공식 열: 정답이 argsort 상위 k 안에 있고 질량이 0.01보다 크면 1점이다.
   - 쓰임: 문헌 비교 표에는 공식 열을, 판정과 곡선 서술에는 동점 반영 열을 쓴다.
3. **DSHM**은 CASANDE `compute_severity_stats`·`compute_f1`을 따른다. 중증은 severity < 3인 17개 질환이다.
   - 계산: 예측과 정답 감별을 모두 0.01 후처리한 뒤 rule-out과 rule-in을 구한다.
     - rule-out = |중증 \ (정답 ∪ 예측)| / max(1, |중증 \ 정답|)
     - rule-in = |중증 ∩ 정답 ∩ 예측| / max(1, |중증 ∩ 정답|)
     - DSH = 2·out·in / (out + in + 1e-10)이고, DSHM은 환자 평균이다.
   - 0점 규약: 정답 감별에 중증이 없으면 rule-in = 0이므로 DSH = 0이다(validation 23.3%).
   - 정답 감별은 CSV `DIFFERENTIAL_DIAGNOSIS`의 확률을 그대로 쓴다.
4. **구간**:
   - Wilson: 환자별 점수의 평균을 p̂로 넣는다(동점 반영은 분수 점수).
   - bootstrap: 환자 단위 백분위 구간이다. numpy `default_rng(0)`으로 반복마다 환자 n명의 색인을 복원추출하고, B = 2,000번 반복한다.
     2.5%·97.5% 분위수를 선형 보간으로 구한다. 한 요약의 모든 지표가 같은 색인을 쓰고, 요약마다 seed 0에서 다시 시작한다.
   - bootstrap 대상: 종료 시점과 보고 예산의 DDF1·DSHM·PER 두 정의, 종료 시점 평균 IL, 짝비교의 IL 차이다.
     IL 차이는 보고 대상 − 비교 대상으로, 같은 환자의 차이 열을 재표본한다.
   - DDR·DDP·macro에는 구간을 붙이지 않는다.
5. **macro GTPA@1**: 그 세트나 부분집합에 정답 환자가 있는 질환마다 평균을 내고, 그 값들을 가중치 없이 평균한다.
   두 정의로, 종료 시점과 보고 예산에서 내며 구간은 없다. 질환별 표는 종료 시점의 환자 수와 두 정의 값이다.
   사전분포로 재가중한 값(데이터 검토 D12)은 내지 않는다.
6. **짝비교**는 같은 환자에서 하고, 방향은 보고 대상 − 비교 대상이다.
   - 비교 쌍:
     - 각 P2 판 대 P1
     - 각 기준선·참조점 대 P1(P2 판 위의 B1 NB와 B6은 그 판과도 비교)
     - B-BED 두 판 대 P1과 P2-value
     - 계층 민감도 판 대 P1과 자기 주 실행
     - 1차 설정 판 대 개정 판
     - 절제 판(A1 두 판, A2, A3 각 ε, A4 (3)·(4), A5) 대 P1, A6 각 판 대 P1과 원래 이진 판(validation에서만)
   - 검정: McNemar(고정 순서 GTPA@1, 정확 검정)는 종료 시점과 각 보고 예산에서 하고, IL 차이는 종료 시점에서 낸다. 부분집합마다 되풀이한다.
   - p값은 다중비교 보정 없이 기술용으로 보고한다. 판정에 쓰는 짝비교는 J2의 P2-binary − P1 하나다(동점 반영 GTPA@1 차이,
     IL 차이 bootstrap 상한). J1·J3′는 단일 정책의 값(Wilson 하한, B-BED의 GTPA@1·평균 IL)으로 판정하고, B-BED 대 P2-value·P1 비교는
     보고만 한다.
7. **B2**는 seed 5개의 평균, 표본 SD(분모 n − 1), 최소–최대를 낸다.
8. **v1 이식판의 IL**은 평균, 중앙값, 95백분위, 최댓값, 그리고 개정 상한(IL 31)을 넘은 비율로 낸다. 1차 기록의 같은 항목은 IL 30 기준이다.

### G. 기준선과 절제 (보완 2 §9 보충)

모든 참조점은 IL과 PER을 보고하지 않는다. 아래에서 '선택 설정'은 주 프로토콜에서 고른 설정을 뜻한다.

1. **B0**
   - 최빈 질환: train 전체의 질환 비율 P(d) = n_d / N(평활 없음)을 모든 환자에게 같은 감별 분포로 낸다.
   - 초기 evidence만: 선택된 P1이 초기 evidence 하나를 반영한 사후다(= P1 예산 0).
2. **B1**
   - 집합 포함: 양성 evidence(기본값 = 음성) 전부를 목록에 담은 질환들에 균등 분포를 준다. 그런 질환이 없으면 모든 지표가 0이다.
   - KB-Bayes: 선택된 P1의 우도표와 균등 사전으로, 223개 evidence 전부의 이진 답을 반영한 사후다.
   - NB: P2 네 판 각각을 그 판의 선택 λ(τ는 쓰지 않음)와 train 전체 빈도로 만든다. 그 판의 응답 단위와 나이·성별 사용 여부 그대로
     223개 evidence 전부를 반영한다. P1, 그리고 같은 판의 주 실행과 비교한다.
   - 참조선 '이진 양성 집합 재대입 다수결': 보고하는 세트 자신(개발은 validation, 평가는 T)의 정답 라벨로 만든다.
     양성 코드 집합(기본값 = 음성)이 같은 환자들의 정답 질환 비율을 감별 분포로 쓴다. 세트의 라벨을 읽으므로 정책이 아니다.
     값을 쓰지 않는 정책이 넘기 어려운 선을 보이는 참조선이다. 부분집합에서도 세트 전체의 비율을 쓴다.
     정책·참조점 가운데 평가 세트의 정답 라벨로 감별 분포를 만드는 것은 이것뿐이다. 데이터셋 성질(`properties.json`)도 정답 질환을
     읽지만 감별을 내지 않는다. 어느 것도 설정 선택에는 쓰지 않는다.
3. **B2**
   - 난수: seed는 0–4이고, 환자마다 `default_rng([seed, 행 번호])`로 만든다.
   - 질문: 매 질문에서 KB 후보(목록 밖 양성 응답이 가장 적은 질환들) 목록의 합집합에서 열린 evidence 하나를 균등 추출한다.
     남지 않으면 열린 evidence 전체에서 균등 추출한다.
   - 순위와 종료: P1과 같다(τ, P1 사후의 최대 EIG < 1e-6, IL 31).
4. **B6**
   - 질문 순서: train 전체에서 그 evidence가 양성인 레코드 수의 내림차순이다. 양성은 이진이면 기록, 범주형·다중선택이면 기본값이 아닌 값이고,
     질환 구분 없이 합산한다. 동점은 KB 순서로 정하고, 열린 것 가운데 앞에서부터 묻는다.
   - 바탕 정책: P1과 P2 네 판 각각이다. 순위와 종료는 바탕 정책 그대로다.
5. **A1**: P1의 질문 순서를 재생하지 않는다.
   - 질문 선택: 같은 EIG 탐욕 규칙이되, A1 자신의 사후(무시한 극성의 답이 빠진 사후)에서 P1 우도표 전체로 EIG를 계산한다.
   - 종료: A1 사후의 최대가 τ 이상, 그 사후의 최대 EIG가 1e-6 미만, IL 31 가운데 먼저 오는 쪽이다.
   - 음성만 판: 초기 evidence도 반영하지 않는다.
6. **A2**: train 전체 P(d), λ = 1.0, 나이·성별 미사용이다. α·ε·τ는 P1 선택값이다.
7. **A4**(계층 절제)는 P1 선택 설정 그대로 validation에서만 돌리는 네 판이다. 보완 2 §9의 세 판에, 데이터 검토 D8의 셋째 축인 (3)을 더한다.
   - (1) 전파 없음: 주 프로토콜이다.
   - (2) 암묵 응답: 계층 민감도의 P1 실행을 그대로 쓴다.
   - (3) 부모 우선: 자식은 부모가 양성으로 알려진 뒤에만 열린다(초기 evidence이거나, 물어서 양성). 부모가 음성이거나 묻지 않았으면
     자식은 닫힌 채로 두고, 답도 채우지 않는다.
   - (4) 자식 금지: 자식 14개를 묻지 않는다. 목록과 우도표에서는 빼지 않는다.
   - 공통: 닫힌 질문은 EIG 하한 판정의 최대 EIG에서 뺀다.
8. **A5**
   - 질문: KB 후보(B2와 같은 정의)의 목록 가운데 가장 많은 목록에 든 열린 evidence를 묻는다. 동점은 KB 순서로 정한다.
   - 대체: 그런 evidence가 남지 않으면 KB 순서로 묻는다.
   - 순위와 종료: P1과 같다.
9. **A6**: P2 이진 두 판 각각의 선택 λ·τ를 그대로 두고 응답만 값 단위로 바꾼다(train 전체). 원래 이진 판, 그리고 P1과 비교한다.
   P2-value가 따로 고른 설정은 쓰지 않는다.
10. **v1 재현과 J4**는 부록용이며, 1차 기록과 같은지 확인하는 것이지 새 판정이 아니다.
    - 판정량: v1 이식판(CUI 그래프, trav1 버그 켬, validation 전체)의 v1 자체 순위 1위 적중률이다. 동점은 노드 ID 오름차순으로 깨고,
      0.01 후처리는 하지 않는다. 81.13% ± 0.5%p 안(경계 포함)이면 충족이다.
    - 보고만 하는 값: 같은 실행의 동점 반영 GTPA@1과 동점 seed 0–9의 범위다.
    - 규칙: v1 규칙은 보완 2 프로토콜이 아니라 v1대로 돈다. 시작 입력은 초기 evidence뿐이고, deny 6과 v15 점수를 쓴다.
      최근 5문항 뒤 순서 있는 top-3가 변하지 않거나 물을 노드가 없으면 멈추고, 최대 223문항까지 묻는다.

### H. 판정 (보완 2 §8 보충)과 예상값

1. **J1·J2를 읽는 곳**: 판정은 모두 T 전체(134,529행, 실패 환자는 0점으로 포함)에서 각 정책의 자체 종료 시점(IL ≤ 31)에 읽는다.
   - J1: P1의 동점 반영 GTPA@1과 공식 GTPA@1 각각의 Wilson 하한을 본다.
   - J2: P2-binary − P1의 동점 반영 GTPA@1 차이와 IL 차이 bootstrap 상한을 본다.
2. **J3′**: 대상은 B-BED 주 판(통계 파일)이다.

1. **경로**:

   - 1차 파일: `protocol_frozen.yaml`, `outputs/dev`, `outputs/eval`은 어느 실행기도 쓰지 않는다. 보존 상태는 `ddxkb.first_run`이 검사한다
     (2026-10-26 통과: protocol af411239…, 동결 a06db1e, 평가 산출 커밋 6910b60).
2. **동결 파일의 내용**:
   - 선택 파일(경로, sha256, 선택 실행 커밋), 평가 세트 T, 부분집합 정의, P1·P2 설정
   - sha256: 매니페스트 다섯 개(T, H1, T-dedup, T-streambench, H2), KB zip, train CSV
   - 예산, 실행 환경
   - 코드 상수: 상한, 계층(주·민감도), 종료(EIG 하한), 동점 허용, 지표(후처리 질량·중증 기준), P2 나이 구간 경계, 통계(bootstrap B·seed),
     넓힌 격자, 절제(A2 λ, A3 ε, A4 규칙), B2 seed, B-BED 규칙과 통계 파일 sha256, 1차 설정, 판정 임계, 공식 질환 순서
   - digest(`config_sha256`)는 나머지 키를 키 정렬·공백 없는 UTF-8 JSON으로 직렬화한 sha256이다. 동결 파일은 그 파일만 바꾸는 커밋 하나로 넣는다.
3. **동결 게이트**: 동결은 `selected.json`의 provenance가 다음 조건을 갖춘 grid 실행의 선택만 받는다.
   - 행 제한이 없는 실행이다(`limit`이 null).
   - 실행을 시작할 때 `paper1/` 안에서 `paper1/outputs/v2/` 밖의 미커밋 변경(미추적 포함)이 없었다.
   - 실행을 시작할 때 `docs/design/` 아래 미커밋 변경이 없었다(A.3).
   - 시작 커밋과 끝 커밋이 같다(A.4).
   - provenance에 KB zip과 train CSV의 sha256이 있고, 매니페스트 다섯 개가 모두 있다.
4. **평가 게이트**: 평가는 다음을 모두 요구한다.
   - `DDXKB_UNSEAL=1`
   - `paper1/`와 `docs/design/` 아래에 수정·삭제·미추적 파일이 없다. 그 밖의 경로는 읽지 않으며, 읽는 데이터는 sha256으로 검사한다.
   - digest가 일치하고, 동결 파일을 바꾼 커밋이 정확히 하나다.
   - 선택 실행 커밋과 HEAD의 `paper1/src`가 같다(A.2).
   - 동결 파일이 가리키는 `selected.json`의 sha256이 동결 값과 같고, 그 선택이 행 제한 없는 실행이며, 동결의 P1·P2 설정이 그 선택과 같다.
   - 평가 세트가 T이고, test CSV의 sha256이 T 매니페스트에 적힌 값과 같다.
   - 매니페스트·데이터·BED 통계 파일의 해시, 코드 상수, 환경이 일치한다.
   - 출력 디렉터리가 1차 출력 안이 아니고, 그 안에 `T/`와 `judgments.json`이 아직 없다.
5. **평가 뒤 수정**: 결함을 고쳐 다시 돌려야 할 때가 있다. 수정은 `paper1/src`를 바꾸므로 같은 동결로는 다시 돌 수 없다.
   - 절차: 동결 파일 경로(`freeze.FROZEN_CONFIG`, 평가 실행기도 이 상수를 읽는다)를 새 이름으로 바꾸는 것까지 수정 커밋에 넣는다.
     그 커밋에서 validation grid를 새 개발 출력 디렉터리(`run_dev --out`)에 다시 돌리고, `freeze --selected <새 selected.json>`으로 동결한 뒤
     새 출력 디렉터리(`run_eval --out`)에서 평가한다. 경로를 grid 뒤에 바꾸면 선택 실행 커밋 이후 `paper1/src`가 바뀐 것이 되어
     평가 게이트(A.2)가 거부한다. 앞 평가의 출력과 앞 동결이 가리키는 `selected.json`은 덮어쓰지 않고, 다시 돌리기 전에 커밋해 둔다.
   - 보고: 두 결과와 수정 커밋을 모두 적는다.
6. **환자별 출력**(jsonl.gz, 결정적 gzip)은 주 정책 다섯 개와 B-BED 두 판만 `patients/`에 쓴다. 입력 sha256과 커밋은 그 상위 디렉터리에 있는
   요약 JSON의 provenance에 있다(주 정책은 `main.json`, B-BED는 `baselines.json`). 동결 digest와 동결 커밋은 T 평가의 요약에만 있다.
   T의 환자별 출력은 재현용이다. 원고에는 집계값과 질환별 표만 쓴다.
